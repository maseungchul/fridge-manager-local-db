# 냉장고 관리 앱 요구사항


## 프로젝트 개요 및 목적

별도 클라우드 서버 없이 로컬 DB로 동작하는 냉장고 관리 앱이다.
실제 냉장고 구조를 반영한 도면에서 재료의 보관 위치를 확인하고, 유통기한·장보기·부부 간 데이터 공유를 관리한다.


## 기능적 요구사항

| 구분 | 내용 |
| --- | --- |
| 기본 사용 | 로그인 없이 기기 내 냉장고 1대를 관리하며, 데이터는 앱 재실행 후에도 유지한다. |
| 냉장고 도면 | 냉장실·냉동실·문·본체·칸·서랍을 등록·편집하고, 위치를 선택하면 해당 재료 목록을 표시한다. |
| 재료 관리 | 재료명·수량·유통기한·위치를 관리하고, 등록·조회·수정·삭제·이동·소비 완료를 제공한다. |
| 영수증 인식 | 영수증을 카메라로 촬영해 구매 항목을 장본리스트에 임시 등록하고, 인식 결과를 수정할 수 있다. |
| 입고 처리 | 장본리스트 항목을 선택한 뒤 도면의 칸·서랍을 선택하고, 부족한 정보를 입력해 재료로 등록한다. |
| 장보기 관리 | 구매할 항목의 추가·수정·삭제·완료 처리를 제공하고, 구매 완료 항목을 장본리스트와 연결한다. |
| 자동 장보기 등록 | 유통기한을 기준으로 장보기 목록에 항목을 자동 등록한다. |
| 유통기한 알림 | 임박·만료 재료의 위치를 도면에 표시하고, 재료명·위치를 포함한 로컬 알림과 사용 재촉 알림을 제공한다. |
| P2P 공유 | 부부의 기기가 각자 관리한 데이터를 실시간 동기화 없이 주고받는다. 통신 방식은 별도 검토한다. |
| 충돌 처리 | 별도 화면에서 충돌 부분을 강조하고, 클릭하면 충돌 내용 중 하나를 선택해 최종 반영한다. |
| 백업·공유 | 설정에서 암호화된 백업 파일을 내보내거나 가져오고, 메신저로 공유할 수 있다. |


## 주요 정책 및 화면 흐름

- 현재 등록 대상은 일반 냉장고이다. 김치냉장고·뚜껑형 지원은 보류하고 조사 자료와 유형 데이터는 보관한다.
- 최초 등록은 단별 문 개수(1~2개)로 배치를 직접 구성하고, 내부 설정에서 여는 방식(왼쪽·오른쪽 열림·서랍형)·문 수납 사용 여부·같은 단의 본체 연결·칸·냉장/냉동을 정한다. 세로 문 합치기와 작은 보조 포켓은 제외한다.
- 내부 설정 도면은 기본 정보와 같은 문 배치로 닫힌 상태에서 시작한다. 문을 누르면 보기 선택 버튼 없이 연결된 본체와 도어 포켓이 함께 열리며 화면 중앙으로 이동한다. 문 한 개의 본체와 포켓은 같은 너비·높이로 표시하고, 공용 본체는 연결된 문 개수만큼 너비를 합산한다. 포켓은 여는 방향에 맞춰 본체 왼쪽·오른쪽에 나란히 배치하고 세로 경첩 두 개로 연결한다. 문 앞면과 뒷면은 같은 경첩을 기준으로 반대 면을 드러내며 회전한다. 열고 닫는 동안에도 본체 프레임과 빈 안쪽 면은 문 뒤에 유지하고, 본체·포켓의 칸과 내부 이름은 문이 완전히 열린 뒤 경첩과 함께 표시한다. 닫기 시작과 동시에 내부 내용과 경첩을 숨긴다. 열린 본체의 `냉장실 / 냉동실` 이름과 `도어포켓` 이름은 내부 상단에 인쇄된 글씨처럼 두고, 칸 영역과 겹치지 않게 공간을 확보한다. 서랍 전면은 아래로 밀려 열린다. 스크롤 밖의 레이어에서 열림·이동을 함께 가감속하고 문이 완전히 열린 상태에서 도면 바깥 배경을 누르면 원래 자리로 복귀하며 닫힌다. 도면의 별도 `닫기` 버튼은 표시하지 않고, 도면 내부·경첩·하단 툴바 조작은 외부 닫기를 실행하지 않는다. 기본정보·내부설정 도면은 실측 치수 대신 공통 표시 비율인 가로:세로 1:2를 사용하고, 기본정보 도면도 이 비율로 세로 길이를 확보한다. 내부설정 도면은 화면 너비를 채우지 않고 최대 높이 540과 남은 공간 안에서 비율을 유지해 중앙에 배치한다. 중앙에 펼칠 때도 닫힌 상태의 본체·도어포켓 크기를 유지하며, 중앙 보기 동안 주변 도면의 스크롤·터치·접근성 탐색을 막는다.
- 중앙의 본체·포켓을 각각 누르면 해당 영역을 선택해 기존 하단 툴바와 내부 설정 패널로 편집한다. 수납을 끈 포켓은 X 표시로 남겨 선택 후 툴바에서 다시 켤 수 있게 하고, 서랍형에는 포켓을 표시하지 않는다. 합치기·분리 후에는 연결된 본체·포켓 배치와 복귀 위치를 다시 계산한다. 보기 상태는 등록 초안과 분리해 도면을 닫아도 기존 입력을 유지한다.
- 중앙 위치는 헤더·툴바 사이의 확정된 레이아웃 크기로 계산하며, 내부 설정 패널을 열거나 닫아도 표시 영역의 크기가 같으면 위치를 유지한다. 여는 방식 선택지는 툴바 위에 겹쳐 표시하고 도면의 표시 영역을 줄이지 않는다. 열린 도면의 여백을 중복 적용하지 않고 실제 테두리를 기준으로 경첩을 배치한다. 본체·포켓 사이에는 경첩과 양쪽 선택선이 겹치지 않을 간격을 확보하며, 이 간격은 닫힌 도면의 문·단 사이 간격에 영향을 주지 않는다.
- 내부설정의 닫힌 도면은 상단 단계 표시 바로 아래에 상단 정렬하고, 두 영역 사이에 추가 간격을 두지 않는다. 기본 정보·내부 설정 도면은 단 사이와 같은 단의 문을 여백 없이 붙여 배치한다. 도어와 본체 프레임은 모든 모서리를 직각으로 표시하며 내부 경계선은 한쪽에서만 그린다. 닫힌 문과 여닫는 문 앞면에는 선택 테두리·선택 그림자를 표시하지 않는다. 열기·열린 상태·닫기에서도 문 앞·뒷면과 본체·포켓 프레임의 직각 모서리를 유지하며 수납 없음 표시와 열린 내부의 선택 테두리에도 동일하게 적용한다. 테두리는 각 문의 실제 영역에만 그리고 열린 문의 원래 자리를 가로지르는 공통 테두리·그림자는 표시하지 않는다. 도면의 비율·크기와 그림자 여백은 유지하고 남는 세로 공간은 아래에 둔다. 중앙 보기의 바깥 닫기는 최상단 제목·헤더 여백에서도 동작하며, 1단처럼 큰 도면이 헤더에 닿아도 제목을 눌러 닫을 수 있다. 기존 헤더 버튼은 그대로 조작할 수 있고, 문을 열고 닫는 중에는 제목 영역 닫기를 막는다.
- 중앙 보기의 좌우 이동 범위는 펼친 도면 양끝의 동일한 여백까지만 허용한다. 한쪽 열림에서 본체를 화면 끝에 정렬한 초기 위치는 해당 방향의 스크롤 한계와 일치해야 한다. 스크롤 표시줄은 도면 아래 별도 공간에 두어 칸과 겹치지 않게 한다. 좌우 이동 안내는 문이 완전히 열리고 좌우 이동이 필요할 때, 제목·툴바를 제외한 도면 표시 영역 중앙에 반투명 안내창으로 약 2초간 표시한 뒤 사라진다. 안내는 터치를 가로채지 않고 사용자 드래그가 시작되면 즉시 숨기며, 자동 위치 정렬에는 종료하지 않는다. 같은 등록 화면에서는 처음 한 번만 표시하고, 내부 설정·여는 방식 패널에 가려진 상태에서는 표시하지 않는다. 표시줄 공간을 추가해도 본체·문 크기와 도면의 세로 중앙 위치는 유지한다.
- 중앙 보기에서는 닫힌 도면의 본체·문 너비와 높이를 그대로 유지하고 위치만 이동한다. 화면 너비·칸 개수에 맞춰 확대하거나 축소하지 않는다. 펼친 너비가 화면을 넘으면 문이 완전히 열린 동안에만 좌우 이동을 허용하고 안내 문구를 표시한다. 가로로 넘친 도면은 닫힌 상태의 크기를 유지한 채 화면의 세로 중앙에 배치한다. 왼쪽 열림은 본체 오른쪽 끝을 화면 오른쪽 여백에 맞추고 그 왼쪽에 도어포켓을 둔다. 오른쪽 열림은 반대로 배치하며, 양쪽에 도어포켓이 있는 합친 본체는 가운데 정렬한다. 영역 선택이나 설정 패널 열기만으로 이동 위치를 초기화하지 않는다. 화면 너비·연결 구조가 바뀌면 이동 범위를 다시 맞추고, 닫을 때는 이동한 위치에서 원래 도면 자리로 복귀한다. 기본 전체 도면의 고정 배치는 유지한다.
- 열고 닫는 중에는 원근 회전으로 커지는 문의 끝이 단계 표시 영역에서 잘리지 않게 한다. 이때 다른 단계의 화면은 숨기고, 전체 도면으로 복귀하면 단계 전환의 잘림을 복원한다.
- 하단 툴바 공간은 중앙 보기 영역에서만 확보한다. 배경 전체 도면의 스크롤 영역은 툴바가 나타나거나 숨겨져도 같은 높이·스크롤 위치를 유지해 아래쪽 문이 잘리지 않게 한다.
- 중앙 보기의 배경 덮개는 툴바가 숨겨진 하단 공간을 포함한 전체 도면 화면을 채운다. 도면의 중앙 위치를 계산하는 영역과 배경을 덮는 영역을 구분해 하단에 색상 띠가 생기지 않게 한다.
- 내부 설정의 도면 화면은 상하 스크롤·튕김 없이 고정하고, 작은 화면에서는 모든 단이 들어오도록 남은 높이에 맞춘다. 기본 정보 입력 화면과 하단 칸 편집 패널은 스크롤을 유지한다.
- 본체 합치기는 같은 단에서 도면상 서로 맞닿은 본체끼리 허용하며, 왼쪽·오른쪽 어느 본체를 선택해도 가능하다. 문 방향·열림 상태·수납 사용 여부는 본체끼리의 맞닿음에 영향을 주지 않는다. 합치지 않은 본체 선택 시 `합치기` 버튼은 항상 표시하고, 이웃 본체가 없거나 합친 칸 수가 최대치를 넘으면 비활성화한다. 합산 칸 수 제한은 버튼의 접근성 설명으로 제공하며, 툴바에 별도 안내 행을 추가해 툴바 높이나 열린 도면의 중앙 위치를 바꾸지 않는다. 합칠 때 칸의 좌우 순서와 선택한 본체의 식별자를 유지하고, 분리할 때는 복귀할 문에 기존 식별자를 남겨 중앙 보기와 복귀 위치를 유지한다. 합친 본체는 `합치기` 대신 `분리`만 표시한다.
- 합친 본체의 문은 기존 여는 방식과 관계없이 왼쪽 문은 왼쪽 열림, 오른쪽 문은 오른쪽 열림으로 바꿔 본체 양쪽에 배치한다. 어느 문을 눌러도 같은 본체와 연결된 포켓을 열고 외관에는 선택 표시를 하지 않으며, 열린 뒤 본체·도어포켓은 개별 선택한다. 문 수납 사용 여부와 칸 입력은 유지한다. 합친 본체는 `여는 방식` 버튼을 비활성화하고 선택 메뉴를 숨긴다. 본체를 분리하면 버튼을 다시 활성화하고 기존 메뉴 열림 상태를 복원한다.
- 본체를 분리할 때는 기존 칸의 순서·이름·서랍 구조를 유지해 나눠 배치한다. 분리할 본체보다 칸이 적을 때만 기본 칸을 추가하며, 합치기·분리 반복으로 칸이 불필요하게 늘어나지 않아야 한다.
- 최초 등록의 단계 이동 버튼은 상단 헤더에 고정한다. 기본 정보는 왼쪽 `취소`·오른쪽 `다음`, 내부 설정은 왼쪽 `이전`·오른쪽 `등록`을 표시한다.
- 문 수납은 `문 수납` 문구 옆의 스위치로 사용 여부를 표시하고 변경한다. 수납을 끈 문은 `내부 설정` 버튼을 비활성화하고, 수납을 켠 문은 수납칸만 편집한다. 보관 모드는 본체 내부 설정에서만 변경하며, 새 본체의 기본값은 냉장이다.
- 문을 열기 전·후와 수납 사용 여부에 관계없이 본체·도어포켓은 설정한 모드의 색상을 유지한다. 냉장은 민트, 냉동은 아이스블루를 쓰며, 열린 내부는 흰 외곽 프레임 안에 닫힌 문보다 한 톤 진한 배경과 밝은 반투명 포켓을 배치한다. 본체의 흰 외곽은 좌우 10px·상하 6px로 표시하고, `냉장실 / 냉동실` 이름 영역까지 흰 바탕으로 표시한다. 넓힌 좌우 여백은 이름 아래 수납 배경에만 적용해 이름의 가로 위치는 유지한다. 그 아래 본체 안쪽의 색 배경에만 10px 둥근 모서리를 적용한다. 도어포켓의 흰 외곽은 6px를 유지하고 이름 영역까지 모드별 배경을 이어 표시한다. 도어 외곽과 선택 테두리는 직각을 유지한다. 선반·포켓 테두리·좌우 구분선·수납 없음 X선까지 같은 모드 색상을 사용한다. 설정 패널의 축소 도면도 같은 색상을 사용한다. 선택 상태는 모드에 맞는 테두리와 옅은 하단 그림자로만 표시하고 별도의 선택 배경은 적용하지 않는다. 미설정 상태는 기본 배경과 중립 회색 선택 테두리를 사용한다.
- 닫힌 문은 연결된 본체의 설정에 따라 선택 여부와 관계없이 모드별 색·그림·이름을 표시한다. 냉장은 민트색·찬 공기 그림, 냉동은 아이스블루·눈송이로 표현하고 중앙 그림 아래에 `냉장실 / 냉동실`을 표시한다. 문 상·하단의 장식 아이콘은 표시하지 않는다. 작은 문은 중앙 그림·글씨 크기를 줄이며, 서랍형은 위쪽 손잡이와 인쇄가 겹치지 않게 한다. 그림과 이름은 문 앞면과 함께 회전하고 합친 본체의 양쪽 문은 같은 모드로 표시한다. 축소 미리보기에도 같은 색과 작은 중앙 그림을 사용한다. 미설정 상태는 기본 색으로 표시하고 이전 모드의 그림은 남기지 않는다. 열린 본체에는 `냉장실 / 냉동실`, 포켓에는 `도어포켓` 이름만 표시하며 별도의 원형 모드 배지는 사용하지 않는다.
- 내부 설정의 전체 도면 화면에서는 툴바를 표시하지 않는다. 문이 완전히 열린 동안에만 해당 본체·포켓에서 선택한 영역의 툴바를 화면 하단에 표시하고, 열고 닫는 중에는 숨기고 조작·접근성 탐색을 막는다. 이동 중에도 툴바 공간을 유지해 중앙 도면이 튀지 않게 한다. 선택 위치는 하단 내부 설정 패널의 제목에 표시한다. `여는 방식` 버튼과 메뉴는 본체 선택 시에만 표시해 연결된 문의 선택지를 툴바 위에 펼친다. 메뉴의 열림 상태는 다른 본체를 선택하거나 본체를 합치기·분리해도 보관하고, 내부 설정 패널을 닫은 뒤에도 유지한다. 포켓 선택 중에는 여는 방식 버튼과 메뉴를 모두 숨기며, 합치지 않은 본체를 다시 선택하면 기존의 열린 상태를 복원한다. `닫기` 또는 `여는 방식` 버튼을 다시 눌러 메뉴를 닫는다. 기기 뒤로가기·접근성 닫기·단계 이동도 기존 흐름을 유지한다. `내부 설정`은 하단 패널에서 칸·보관 모드를 편집한다. 변경은 초안에 즉시 반영하고 선택지·패널을 닫아도 입력을 유지한다.
- 설정 패널 상단에는 선택 영역의 축소 미리보기를 고정한다. 문·본체 모두 오른쪽 위에 냉장·냉동 버튼, 아래에 기본 정보의 문 개수와 같은 `− 칸 N개 +` 조절과 최대 칸 개수 안내 문구를 묶어 상하 양끝으로 배치한다. 문에서는 연결된 본체의 보관 모드를 선택 상태로 표시하고 냉장·냉동 버튼은 비활성화한다. 보관 모드 제목은 표시하지 않고, 본체는 아래 스크롤 영역에서 칸별 좌우 분할을 편집하고, 도어포켓은 개별 칸 편집 영역 없이 내용 높이에 맞춘 패널로 표시한다. 배경은 제자리에서 흐려지고 패널만 아래에서 올라온다.
- 칸 이름을 직접 입력하지 않고 본체·도어포켓 도면과 축소 미리보기에는 칸명을 표시하지 않는다. 설정 패널·접근성 안내·내부 데이터에는 위에서부터 `위에서 N번째 칸`으로 자동 지정하고, 좌우 분할은 `왼쪽 / 오른쪽`으로 구분한다. 본체 합치기·분리 후에는 현재 영역의 순서로 위치명을 다시 지정하며 DB의 이름 필드는 유지한다.
- 기본 흐름: `첫 실행 → 냉장고 등록 → 홈 도면 → 위치 선택 → 재료 목록·관리`.
- 홈은 냉장고·장보기·설정으로 구성하며, 기존 `fridge-manager`의 도면과 사용 흐름을 참고한다.
- `장보기 목록`은 구매 예정 항목, `장본리스트`는 구매 후 보관 위치를 지정하기 전의 임시 항목이다.
- 본체의 칸 구조는 아이콘과 함께 `분할 없음 / 좌우 2칸`으로 선택한다. 내부 칸에는 서랍 손잡이를 표시하지 않고, 여는 방식이 서랍형인 본체에만 손잡이를 표시한다. 재료가 있는 위치의 삭제·구조 변경은 재료를 먼저 이동·삭제한 후 처리한다.
- 본체는 최대 4칸, 도어포켓은 최대 3칸까지 구성하고, 본체 합치기도 합산 4칸까지만 허용한다. 일반 문과 서랍형의 손잡이는 같은 크기·모양의 막대형으로 표시하며, 일반 문은 세로·서랍형은 가로로 배치한다. 손잡이와 경첩은 냉장에서는 연한 민트, 냉동에서는 연한 블루그레이를 사용하고 미설정 상태에서는 연한 중립 회색을 사용한다. 그림자는 옅은 중립 회색으로 표시한다. 경첩은 짧은 캡슐 형태로 표시하며 테두리·연결판·하이라이트는 표시하지 않는다. 경첩은 문이 완전히 열린 동안에만 표시하고, 닫기 시작과 동시에 숨긴다.
- 외관·본체·포켓·공간 이름·축소 미리보기는 크림·민트·아이스블루 계열의 일러스트 표현을 공유한다. 직각 프레임·밝은 내부 면·옅은 그림자로 두께를 표현하고 손잡이·경첩은 둥근 형태로 단순화한다. 금속 질감과 강한 입체 음영은 사용하지 않으며, 주변 화면 배경과 버튼의 색상은 유지한다.
- 도어포켓은 모드에 맞는 밝은 민트·아이스블루의 반투명 전면판과 둥근 바닥으로 표현하고 전면의 세로 리브선은 표시하지 않는다. 윗모서리는 굴곡 없이 직각으로 표시하고, 상단 입구에는 배경보다 진한 10px 직선 테두리를 사용한다. 양끝 막대 없이 옅은 하단 그림자로 바구니 형태를 표시한다. 뒤쪽 테두리와 전면 상단 안쪽의 가는 보조선, 하단의 겹선은 표시하지 않는다. 수납함은 칸 크기에 맞춰 표시하며, 장식은 선택·스크롤 터치와 접근성 탐색을 가로채지 않는다. 도면과 칸의 전체 크기는 유지한다.
- 본체의 가로 칸 경계는 둥근 단면의 모드별 민트·아이스블루 선반과 아래로 부드럽게 번지는 그림자 하나로 표시하고 윗면·겹선은 표시하지 않는다. 좌우 분할선은 프레임과 같은 모드별 옅은 색을 사용한다. 칸 크기와 선택·스크롤 동작은 유지한다.
- 재료 변경 시 관련 알림을 갱신하고, 삭제·소비 완료 시 취소한다.
- 공유 데이터는 즉시 적용하지 않는다. 충돌을 강조한 화면에서 내용을 비교·선택하고, 최종 반영 전까지 기존 데이터를 유지한다.
- 백업 파일 병합에도 같은 충돌 처리 절차를 적용하며, 새 설치 환경에서도 복원할 수 있어야 한다.


## 비기능적 요구사항

| 구분 | 내용 |
| --- | --- |
| 오프라인 | 냉장고·재료·장보기의 핵심 기능은 인터넷과 서버 없이 동작한다. |
| 저장 안정성 | `expo-sqlite` 기반으로 관계·트랜잭션·DB 버전을 관리하고, 업데이트 시 기존 데이터를 보존한다. |
| 데이터 보호 | 공유 상대를 확인하고 데이터를 보호하며, 저장·병합·복원 실패나 잘못된 백업 파일로 기존 데이터가 손상되지 않아야 한다. |
| 데이터 일관성 | 냉장고 구조와 재료 위치 관계를 유지하고, 같은 공유 데이터를 중복 반영하지 않는다. |
| 권한 처리 | 카메라·알림 권한을 거절해도 수동 등록과 조회는 사용할 수 있다. |


## 추가 검토 사항

- P2P 통신 방식, 상대 기기 등록 절차와 공유 범위.
- 충돌 판정·선택 단위와 수정·삭제·구조 변경 간 충돌 처리.
- 클라우드 서버에 의존하지 않는 영수증 인식 방식과 사진 보관 여부.
- 입고 시 드래그앤드롭 지원 여부.
- 자동 장보기 등록 시점·수량·중복 방지 기준.
- 유통기한 필수 여부, 임박 기준과 알림 시점·반복 주기, 소비 이력 보관 여부.
- 백업 암호화·암호 전달 방식과 전체 복원·병합 정책.
