# fridge-manager-local-db

냉장고 도면으로 **재료를 어디에 보관했는지 바로 확인**하고, 유통기한을 관리해 **식재료의 낭비를 줄이는 모바일 앱**을 개발하고 있습니다.

기기 내 SQLite를 이용한 로컬 저장을 기본으로 하며, 향후 중앙 서버 동기화를 통한 가족 공유로 확장할 계획입니다.

## 해결하려는 문제

- 냉장고 안쪽에 넣어 둔 재료를 잊거나 보관 위치를 찾기 어려운 문제
- 유통기한이 지난 뒤 발견해 먹지 못하고 버리는 문제
- 이미 보관 중인 재료를 확인하지 못해 중복 구매하는 문제

## 주요 기능 및 개발 현황

| 기능 | 내용 | 상태 |
| --- | --- | --- |
| 냉장고 도면 구성 | 문 배치·냉장/냉동·칸 수·좌우 분할 설정, 본체 합치기·분리 | UI 구현 |
| 로컬 저장 | 냉장고 구성을 SQLite에 저장·수정 | 등록·편집 저장 연결 |
| 재료 관리 | 도면의 보관 위치를 선택해 재료 등록·조회·수정·이동·소비 처리 | 개발 예정 |
| 유통기한 관리 | 임박·만료 재료 확인과 알림으로 먼저 사용할 재료 안내 | 개발 예정 |
| 장보기 관리 | 구매할 항목을 관리하고 구매 후 냉장고 입고로 연결 | 개발 예정 |

냉장고 등록·도면 편집 UI와 DB 저장·수정을 연결했습니다. 홈 상단의 편집 아이콘으로 저장된 구성을 수정하고, 저장 후 홈 도면을 갱신합니다. 홈도 등록 화면의 도면 컴포넌트를 공유하며, 저장된 전체 배치에서 문을 열고 닫아 본체·도어포켓을 확인합니다. 냉장고·장보기·설정을 OS 기본 하단 탭으로 전환하며, 장보기·설정은 기본 화면만 연결했습니다. 재료 관리 기능은 아직 연결되지 않았습니다.

## 목표 사용 흐름

냉장고 구성 → 재료 등록·보관 위치 지정 → 도면에서 위치별 재료 확인 → 소비·이동·장보기 관리

## 추후 개발 사항

- **가족 공유:** local-first + 중앙 서버 동기화 방식을 채택합니다. 오프라인에서도 기기에서 데이터를 관리하고, 연결 후 변경 사항을 동기화해 가족이 함께 냉장고 현황을 확인하는 것을 목표로 합니다.
- **구매 목록 자동 등록:** 영수증 사진 OCR 또는 영수증 바코드 기반 구매 목록 API 활용을 검토합니다. 구매 항목을 가져온 뒤 내용을 확인·수정하고 보관 위치를 지정해 재료로 등록하는 흐름을 계획하고 있습니다.

## 기술 스택

Expo · React Native · TypeScript · SQLite (`expo-sqlite`)

## 실행

```bash
npm install
npm start
```
